# 앱 업데이트

## 사용자 동작

- 배포 앱은 시작할 때 새 버전을 확인하고 다운로드·서명 검증·설치 후 재시작한다.
- 시작 확인은 최대 10초, 다운로드는 최대 5분으로 제한한다. 실패하면 기존 앱으로 계속 진행한다.
- 확인·다운로드 중 **나중에 업데이트**를 누르면 바로 앱을 사용할 수 있다. 다운로드는 계속되지만 자동 설치는 취소된다.
- 실행 중에는 30분마다 확인한다. 창으로 돌아오거나 네트워크가 복구됐을 때도 마지막 확인에서 30분이 지났으면 확인한다.
- 실행 중 받은 업데이트는 **업데이트하고 재시작** 버튼을 누를 때 적용한다. 모드 작업·다운로드·가져오기 확인이 진행 중이면 버튼이 비활성화된다.
- 설정에서 현재 실행 버전, 업데이트 상태와 변경 사항을 확인하고 재시도할 수 있다.
- 개발 빌드에서는 실제 업데이트를 확인하지 않는다. 브라우저 미리보기는 모의 API를 사용한다.

## 서명 키와 최초 배포

무료 Tauri 서명 키를 사용한다. 현재 설정의 공개 키와 짝을 이루는 비밀 키는 이 작업 환경의 `.local/updater.key`에 생성했다. `.local/`은 Git에서 제외되며, 비밀 키는 파일 권한 600으로 보관한다. 키 내용은 앱이나 저장소에 포함하지 않는다.

**첫 배포 전에 비밀 키를 안전한 별도 위치에 백업한다.** 키를 잃으면 기존 설치본이 신뢰하는 업데이트를 만들 수 없다. 이 키에는 암호를 설정하지 않았으므로 파일 자체를 비밀로 유지한다.

GitHub 저장소의 Actions secrets에 다음 값을 등록한다.

| Secret | 값 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | `.local/updater.key` 파일의 전체 내용. 파일 경로가 아님 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 현재 키는 암호가 없으므로 생략 가능 |

이 변경은 로컬 구현이며, GitHub secret 등록이나 릴리스 게시는 실행하지 않았다. 기존 배포 앱에는 업데이터가 없으므로 업데이터가 포함된 버전을 한 번 직접 설치해야 한다.

업데이트용 키는 운영체제의 코드 서명 인증서와 별개다. macOS는 ad-hoc 서명을 사용하며, macOS 실행 허용이나 Windows SmartScreen 경고가 남을 수 있다.

## 릴리스 절차

1. `package.json`, `frontend/package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`의 버전을 동일하게 올린다. 필요한 잠금 파일도 갱신한다.
2. 커밋을 준비하고 같은 버전의 `vX.Y.Z` 태그를 push한다. 기존 태그는 Release 워크플로에서 수동으로 실행할 수도 있다.
3. Release 워크플로가 검사 후 macOS ARM64, Windows x64, Linux x64용 파일을 빌드한다. `tauri.release.conf.json`을 적용하는 릴리스 빌드에서만 업데이트 아티팩트 서명이 필요하다.
4. 모든 빌드가 성공하면 서명 파일과 `latest.json`을 합쳐 **초안 릴리스**를 만든다. 불완전한 플랫폼 구성은 거부한다. 생성된 릴리스 노트는 앱의 변경 사항에도 포함된다.
5. 각 OS에서 이전 버전 → 후보 버전으로 설치·재시작을 검증한 뒤 초안을 정식 최신 릴리스로 공개한다. 사전 릴리스로 게시하면 정식 업데이트 채널에는 노출되지 않는다.

앱은 `https://github.com/KGH1113/ADOFAIModManager/releases/latest/download/latest.json`을 확인한다. 저장소를 이전하면 이 주소와 릴리스 생성 설정을 함께 검토해야 한다.

같은 태그의 릴리스가 이미 있으면 워크플로는 기존 배포를 덮어쓰지 않고 실패한다. 새 버전 태그를 사용한다. 아직 `latest.json`이 없는 경우 설정에서는 업데이트 확인 오류가 표시되지만 앱 시작은 계속 진행한다.

## 지원 범위와 검증

- Windows는 NSIS 설치 프로그램, macOS는 `.app.tar.gz`, Linux는 **AppImage**로 업데이트한다. Linux `.deb` 설치본의 자동 업데이트는 지원 대상으로 삼지 않는다.
- macOS Intel 빌드는 현재 배포 매트릭스에 없으며, 추가 시 manifest 생성기의 대상 목록도 확장해야 한다.
- 업데이트 파일은 다운로드 후 서명과 서명된 버전까지 검증한다. 설치 직전에는 네이티브 엔진 잠금과 모드 다운로드 상태도 확인한다.
- 다운로드는 프로세스 메모리에 보관하므로 설치 전에 앱을 종료하면 다음 실행에서 다시 다운로드한다.
- 자동화 검사: `bun run check`, `bun run check:release`, `bun run check:desktop`, `bun run frontend:build`.
- 상태 전이 테스트는 시작 설치, 나중에 설치, 중복 확인, 주기 확인, 작업 잠금, 다운로드·검증 실패, 설치 실패 후 재시도를 다룬다. 화면 테스트는 Strict Mode에서 한 번 확인하는지와 재시작 버튼 잠금을 검증한다.
- 실제 OS의 앱 교체·재시작은 공개 릴리스 전 플랫폼별 배포본으로 확인해야 한다. 단위 테스트는 이 과정을 대체하지 않는다.

공식 동작: [Tauri Updater](https://v2.tauri.app/plugin/updater/), [macOS 서명](https://v2.tauri.app/distribute/sign/macos/), [Windows 서명](https://v2.tauri.app/distribute/sign/windows/).

## 이번 구현의 검증 결과

- 프런트엔드 타입 검사와 테스트 126개 통과. 기존 `umm-shortcut.test.ts`의 non-null assertion 경고 1개는 남아 있다.
- 릴리스 manifest 테스트 3개, Rust 테스트 10개 통과. 외부 TUF API를 사용하는 기존 Rust 테스트 4개는 기본 설정대로 제외했다.
- 프런트엔드 프로덕션 빌드와 GitHub Actions `actionlint` 검사 통과.
- macOS ARM64 릴리스 앱, 약 93 MB의 업데이트 압축 파일과 `.sig` 생성 성공. 공개 키 일치, 비밀 키 파일 권한 600, 서명의 앱 버전 포함을 확인했다.
- 브라우저 연결이 제공되지 않아 실제 브라우저 시각 검사는 진행하지 못했다. 설정 및 업데이트 UI는 컴포넌트 테스트로 검증했다.
- Windows/Linux 실물 설치, macOS에서 이전 설치본을 실제 교체하고 재시작하는 과정, GitHub 워크플로 실행은 아직 검증하지 않았다.
