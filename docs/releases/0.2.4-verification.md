## 자동 업데이트 서명 보완

- 기존 Linux AppImage 재포장 단계는 `tauri signer sign`에 앱 버전을 전달하지 않았다. 이로 인해 서명의 trusted comment에 버전이 빠져 `requireSignedVersion` 검증에서 거부될 수 있었다.
- 배포 워크플로에 `--app-version`을 추가하고, 매니페스트 생성 및 업로드 검증에서 서명 버전 누락·불일치를 거부하도록 수정했다. 수정 커밋은 `d9a4fb5fb5e7b610e4ad7df41d633bb13cbcad4b`다.
- 이번 0.2.4는 [초안 서명 보정 작업](https://github.com/KGH1113/ADOFAIModManager/actions/runs/42268184433)을 통해 앱 파일을 변경하지 않고 Linux 서명과 `latest.json`, 릴리스 노트만 공개 전에 보정했다. 일회성 보정 워크플로는 작업 후 제거했다.
- 공개 전 세 플랫폼의 실제 다운로드 파일을 앱에 내장된 공개키로 검증했다. 파일 서명, 매니페스트의 서명과 `.sig` 내용, 서명된 버전 `0.2.4`가 모두 일치했다.

## macOS 실제 앱 및 업데이트 확인

- 공개 전 배포 후보 앱에서 정상 메인 화면, `Assembly patch` 설치 방식 표시, 설정의 `0.2.4`, `Español (Latinoamérica)` 선택지를 확인했다.
- 별도 임시 폴더의 정식 0.2.3 앱에서 공개 채널의 0.2.4를 감지하고 `Update and restart`를 실행했다.
- 앱 번들의 버전이 0.2.4로 바뀌었고 새 프로세스가 시작됐다. 교체된 앱의 `codesign --verify --deep --strict` 검사가 통과했다.
- 교체된 실행 파일과 CI 배포 후보의 SHA-256은 모두 `e6d399be6beebc76b2a34193353e349385ee3ccd8c32f4ce8c7b9f8969d398a9`로 일치했다.
- 자동 재시작 직후 컴퓨터 사용 도구에서 창에 연결하지 못해 검증용 프로세스를 종료하고 교체된 앱을 다시 열었다.
- 다시 연 앱에서 정상 메인 화면과 설정의 `0.2.4`, `You're up to date.` 상태를 확인했다.
- Windows/Linux는 CI·배포 엔진·실제 업데이트 파일 서명을 검증했다. 해당 OS의 GUI 설치·재시작은 이 환경에서 검증하지 않았다.

검증은 임시 앱 복사본을 사용했으며 기존 게임과 설치된 모드는 변경하지 않았다.
