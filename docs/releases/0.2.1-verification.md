## 배포 파일과 업데이트 채널

- 기존 0.2.0과 업데이트 공개 키 및 채널 주소가 동일하다.
- macOS ARM64 `.app.tar.gz`, Windows x64 NSIS `.exe`, Linux x64 `.AppImage`를 다운로드해 앱의 공개 키로 서명을 독립적으로 검증했다.
- `latest.json`의 세 플랫폼 URL과 서명은 실제 업로드 파일과 일치한다.
- 정식 최신 릴리스로 공개한 뒤 인증 없는 `/releases/latest/download/latest.json` 응답의 버전이 `0.2.1`인 것을 확인했다.
- 세 플랫폼의 공개 다운로드 URL 모두 HTTP 200 및 예상 파일 크기를 반환했다.

## macOS 실제 앱 확인

- 공개 전 후보 앱을 실행해 설정 화면의 `0.2.1` 표시와 정상 메인 화면 진입을 확인했다.
- 정식 0.2.0 앱의 별도 복사본을 실행하자 공개 업데이트 채널에서 0.2.1을 자동 다운로드하고 설치했다.
- 설치 전 프로세스 PID는 `66278`, 교체 후 실행된 프로세스 PID는 `66619`였다.
- 설치된 앱의 버전이 `0.2.1`로 바뀌었고 `codesign --verify --deep --strict`가 통과했다.
- 교체된 실행 파일과 CI 배포 후보 실행 파일의 SHA-256이 모두 `2a7c6da99c54f5322f3d16e08a3633f43c79d76d6dab725a776a2d1e4047f2f3`으로 일치했다.
- 재시작 과정에서 UI 연결이 끊겨 업데이트된 앱을 다시 열었다. 설정 화면의 `0.2.1`과 `최신 버전을 사용 중이에요.`를 확인했다.
- Windows/Linux는 CI 빌드·테스트 및 업데이트 파일 서명을 검증했다. 해당 OS의 실제 GUI 교체·재시작은 이번 환경에서 검증하지 않았다.
