# 창 크기와 저해상도 화면 대응

창을 자유롭게 조절할 수 있도록 변경했다. 일반적인 화면에서는 다음 크기를 사용하며, 단위는 OS 배율을 반영한 논리 픽셀이다. Windows의 제목 표시줄과 테두리는 이 콘텐츠 크기에 별도로 더해진다.

| 항목 | 너비 × 높이 |
| --- | --- |
| 기본 크기 | 1120 × 780 |
| 최소 크기 | 900 × 560 |
| 최대 크기 | 1240 × 860 |

최대화는 비활성 상태를 유지한다. 큰 모니터에서도 콘텐츠에 비해 창이 지나치게 커지는 것을 막기 위한 제한이다.

## 실행 및 모니터 변경

앱을 실행할 때 현재 모니터의 작업 영역에서 창 테두리와 각 방향 12 논리 픽셀의 여유 공간을 제외한 크기를 계산한다. 기본 크기가 이 영역을 초과하면 해당 방향만 줄이고, 작업 영역 중앙에 표시한다. 크기 계산이 끝날 때까지 창을 숨겨 큰 창이 잠깐 나타나는 현상을 방지한다. 매 실행 시 이 정책을 적용하며, 사용자가 조절한 크기를 별도로 저장하지는 않는다.

예를 들어 1366 × 768 모니터에서 작업표시줄을 제외한 높이가 728이고 창 테두리가 16 × 39인 100% 배율 환경에서는 콘텐츠 크기가 1120 × 665로 시작한다.

사용 가능한 공간이 900 × 560보다도 작으면 네이티브 최소·기본·최대 크기와 WebView 배율을 함께 낮춘다. 글자·버튼·미리보기를 같은 비율로 축소해 레이아웃 공간을 유지한다. 일반적인 크기의 화면에서는 WebView 배율이 100%다.

모니터를 옮기거나 배율이 바뀌면 작업 영역에 맞게 제한을 다시 적용한다. 현재 크기가 새 범위 안에 있으면 유지하고, 범위를 벗어나면 보정한다. 같은 모니터 안에서 창을 이동할 때는 위치를 보정하지 않는다. 모니터 조회나 크기 적용에 실패해도 오류를 기록하고 창을 표시한다.

작업 영역과 배율의 단위는 [Tauri Monitor 문서](https://docs.rs/tauri/latest/tauri/window/struct.Monitor.html)를 기준으로 처리한다.

## 레이아웃

- 낮은 창에서는 제목·카드의 여백을 줄이고 영상·이미지에 남은 높이를 배분한다.
- 초기 설정 화면은 스크롤 없이 설명과 진행 버튼을 표시한다. Steam 안내에서 게임을 찾지 못했을 때는 폴더 선택과 새로고침을 간결하게 표시한다.
- 키 배치 화면은 창 너비·높이에 따라 일반 키 한 칸의 크기를 52~72px 기준으로 조절하고, 남은 공간이 부족하면 추가로 축소한다. 배치 비율을 유지하면서 글자·패딩·모서리도 함께 조절하며, 작은 창에서는 손 안내 영역에 최소 140px를 배분한다.
- 설정 창도 최소 높이에서 스크롤 없이 표시한다.
- TUF 안내는 두 옵션을 같은 너비로 나란히 표시한다. 모드 이름과 설치 버튼을 각 영상 위에 정렬하고, 아래에 핵심 설명을 배치한다. 두 영상은 16:9 비율과 같은 크기를 유지하며, 900 × 560 창에서 각각 약 397 × 223px다. 높이 700px 이하에서는 상세 설정 설명을 정보 버튼으로 열어 영상 공간을 확보한다. 더 높은 창에서는 상세 설명도 바로 표시한다. 높이 620px 이하에서는 중복되는 상단 부제를 생략한다. 두 모드의 독립 설치, 키보드 조작, 모션 감소 설정, 미디어 실패 안내를 유지한다.
- 모드 목록·모드 설명·로그처럼 데이터 길이가 늘어나는 영역의 내부 스크롤은 유지한다.

## 검증

- `bun run check`: 타입 검사, Biome, 스크립트 검사 5개, 프런트엔드 테스트 97개 통과.
- `cargo test --manifest-path src-tauri/Cargo.toml`: 10개 통과, 기존 외부 환경 의존 테스트 4개 무시.
- `bun run frontend:build`: 배포용 빌드 성공.
- 창 크기 계산 테스트: 일반 화면, 작업표시줄·창 테두리가 있는 저해상도 화면, 125%·200% 배율 및 최소 크기보다 작은 화면.
- 키 박스 반응형 검사: 5개 창 크기 × 3개 언어 × Key4·8·10·12·16의 75개 조합에서 키 이름과 컨트롤의 잘림·스크롤을 확인했다. 일반 키 한 칸은 900 × 560에서 52px, 1120 × 780에서 66.3px, 1240 × 860에서 72px로 표시된다.
- TUF 영상 반응형 검사: 8개 창 크기 × 3개 언어의 비교 화면 24개 조합과 최소 창의 상세 정보 팝업 6개 조합에서 잘림·스크롤이 없고 두 영상의 크기와 비율이 일치함을 확인했다. 상세 정보의 키보드 닫기와 두 모드의 독립 설치 및 상태 유지도 테스트했다.

브라우저 레이아웃 검사는 한국어·영어·중국어에서 900 × 560, 900 × 860, 1240 × 560, 1120 × 780, 1240 × 860 크기를 사용했다. 초기 설정 11단계와 게임 미탐지 화면 168개 조합, 관리 화면 4개와 설정 창 75개 조합에서 표시 중인 콘텐츠의 잘림이 없음을 확인했다. 초기 설정과 설정 창에는 스크롤이 발생하지 않았다. 실제 Windows 모니터의 DPI 변경·네이티브 창 테두리 동작은 이 환경에서 직접 확인하지 않았다.
